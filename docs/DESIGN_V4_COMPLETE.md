## 1. 기존 시스템 vs 새 시스템

### 기존 시스템 (V3)

```
프로그램 시작 → 모드 선택 (라디오 버튼)

○ 반자동 모드
  - 매수: 수동 (Upbit에서 직접)
  - DCA/익절/손절: 자동
  - 설정: dca_config.json (모든 코인 공통)

○ 완전 자동 모드
  - 매수: 자동
  - DCA/익절/손절: 자동
  - 설정: auto_trading_config.json
  - 전역 리스크 관리
```

**문제점:**
- 코인마다 다른 설정 불가능
- 모드 선택이 양자택일 (유연성 부족)
- 한 코인만 특별히 관리하고 싶어도 불가능

### 새 시스템 (V4)

```
프로그램 시작 → 그룹 생성 및 코인 배치

📁 그룹 A (대형코인)
  ├─ 코인: BTC, ETH
  ├─ 매수: 자동 (50,000원)
  ├─ DCA: 자동
  ├─ 익절: 자동
  └─ 손절: 자동

📁 그룹 B (알트코인)
  ├─ 코인: DOGE, XRP
  ├─ 매수: 수동
  ├─ DCA: 자동
  ├─ 익절: 알림만
  └─ 손절: 자동

📁 그룹 C (실험)
  ├─ 코인: SOL
  ├─ 매수: 자동 (30,000원)
  ├─ DCA: 사용 안 함
  ├─ 익절: 알림만
  └─ 손절: 자동
```

**개선점:**
- ✅ 그룹마다 다른 설정 가능
- ✅ 코인별 세밀한 제어
- ✅ 무제한 그룹 생성
- ✅ 단독 코인 = 새 그룹 생성
- ✅ 모드 라디오 버튼 삭제 (간소화)

## 2. 핵심 개념: 그룹 시스템

### 그룹이란?

**정의**: 동일한 거래 설정을 공유하는 코인들의 묶음

**특징:**
- 무제한 생성 가능
- 그룹 내 모든 코인은 동일한 설정 공유
- 그룹 간 코인 이동 가능
- 개별 코인 특수 설정 = 새 그룹 생성

### 사용 예시

#### 케이스 1: 전략별 분류
```
📁 보수적 전략
  - BTC, ETH
  - 익절 +15%, 손절 -5%

📁 공격적 전략
  - DOGE, SHIB
  - 익절 +8%, 손절 -10%
```

#### 케이스 2: 관리 방식별 분류
```
📁 완전 자동
  - 매수 자동, 모든 것 자동

📁 수동 진입 + 자동 관리
  - 매수 수동, DCA/익절/손절 자동

📁 관찰만
  - 모든 것 알림만
```

#### 케이스 3: 단독 코인 특별 관리
```
📁 BTC 전용
  - BTC만 포함
  - 특별한 설정 적용
```

## 3. 매수/매도 설정 (3가지 옵션)

### 핵심 아이디어

> "모드 1, 2, 3으로 나누지 말고, 각 기능을 독립적으로 켜고 끄자!"

### 매수 방식 (2가지)

```
○ 자동 매수
  - 프로그램이 매수 신호 감지 시 자동 실행
  - 매수 금액 설정 필요

○ 수동 매수
  - 사용자가 Upbit에서 직접 매수
  - MyAsset WebSocket으로 감지 후 관리 시작
```

### DCA / 익절 / 손절 (각각 3가지 옵션)

```
✅ 자동 실행
  - 조건 도달 시 자동으로 주문 실행
  - 텔레그램 알림도 전송

🔔 알림만
  - 조건 도달 시 텔레그램 알림만
  - 자동 실행 안 함
  - 사용자가 직접 판단

❌ 사용 안 함
  - 조건 체크도 안 함
  - 알림도 없음
```

### 조합 예시

#### 완전 자동 (기존 모드 1)
```
매수: 자동
DCA: 자동
익절: 자동
손절: 자동
```

#### 반자동 (기존 모드 2)
```
매수: 수동
DCA: 자동
익절: 자동
손절: 자동
```

#### 보수적 하이브리드
```
매수: 자동
DCA: 자동 (평단가 개선)
익절: 알림만 (큰 수익 노림)
손절: 자동 (손실 제한)
```

#### 공격적 하이브리드
```
매수: 자동
DCA: 알림만 (신중하게 물타기)
익절: 알림만 (최대 수익)
손절: 자동 (손실만 차단)
```

#### 완전 수동
```
매수: 수동
DCA: 알림만
익절: 알림만
손절: 알림만
```

## 4. 전역 설정

### 기존 시스템의 전역 설정 (완전 자동 모드)

```
❌ 매수 금액: 10,000원 (삭제됨 → 그룹별로 이동)
❌ 스캔 주기: 60초 (보류 → 자동매수 로직 결정 후)
❌ 모니터링 설정 (삭제됨 → 그룹에 직접 코인 추가)
❌ 일일 거래 횟수 제한 (삭제됨 → DCA가 막힐 수 있음)
✅ 최대 포지션 수 (유지)
✅ 최소 KRW 잔고 (유지)
✅ 일일 손실 한도 (수정됨)
```

### 새 시스템의 전역 설정 (리스크 관리 3가지)

#### 1️⃣ 최대 포지션 수 제한
```json
{
  "max_positions": {
    "enabled": true,
    "limit": 3
  }
}
```

**동작:**
- 자동매수 시에만 체크
- 포지션 N개 도달 → 새 자동매수 거부
- DCA는 기존 포지션이므로 영향 없음
- 수동 매수는 체크 안 함 (사용자 책임)

**예시:**
```
현재 포지션: BTC, ETH, DOGE (3개)

SOL 자동매수 신호 발생
→ 거부: "최대 포지션 3개 도달"
→ 텔레그램 알림: "SOL 매수 신호 발생했으나 최대 포지션 제한"

BTC DCA 조건 도달
→ 실행 가능 (기존 포지션 추가 매수)
```

#### 2️⃣ 최소 KRW 잔고 유지
```json
{
  "min_krw_balance": {
    "enabled": true,
    "amount": 50000
  }
}
```

**동작:**
- 자동매수/DCA 실행 전 체크
- 잔고가 이 금액 이하 → 매수 거부
- 비상 자금 확보

**예시:**
```
현재 KRW 잔고: 60,000원

BTC 자동매수 신호 (50,000원)
→ 매수 후 잔고: 10,000원 < 50,000원
→ 거부: "최소 잔고 미달"
```

#### 3️⃣ 일일 손실 한도 (신규 옵션 추가)
```json
{
  "daily_loss_limit": {
    "enabled": true,
    "loss_pct": 10.0,
    "calculation_method": "daily_only",
    "action": "alert"
  }
}
```

**설정 항목:**
- `loss_pct`: 손실 한도 (1% ~ 50%)
- `calculation_method`:
  - `"daily_only"`: 당일 거래 손익만 계산 (기본값)
  - `"total_account"`: 계좌 전체 평가 (미구현)
- `action`: 도달 시 동작
  - `"alert"`: 알림만 (기본값)
  - `"liquidate"`: 전체 매도

**동작 - 옵션 A: 알림만**
```
계좌 손실 -10% 도달

1. 텔레그램 알림:
   "⚠️ 일일 손실 한도 도달! (-10%)
    신규 매수를 중지했습니다.
    포지션은 유지 중입니다."

2. 제한적 거래:
   - 자동매수 중지 ❌
   - DCA 중지 ❌
   - 익절 계속 ✅ (회복 시 수익 실현)
   - 손절 계속 ✅ (추가 손실 방지)

3. 다음날 09:00 리셋 시 재개
```

**동작 - 옵션 B: 전체 매도**
```
계좌 손실 -10% 도달

1. 모든 포지션 시장가 즉시 매도

2. 텔레그램 알림:
   "🚨 일일 손실 한도 도달! (-10%)
    모든 포지션을 청산했습니다.

    청산 내역:
    • BTC: -50,000원
    • ETH: -30,000원

    총 손실: -80,000원"

3. 거래 완전 중지

4. 다음날 09:00 리셋 시 재개
```

**일일 리셋 시점:**
- **오전 9시** (업비트 등락률 리셋 시간)
- 매일 09:00:00에 카운터/상태 초기화

**손실 계산 방법 (daily_only):**
```
[09:00] 거래일 시작 - 스냅샷 생성
  - 시작 평가액: 기존 보유 코인 평가액
  - 시작 KRW: 현금 잔고

[10:00] ETH 자동매수 (100,000원)

[11:00] 손실 계산
  - 기준 자본: 09:00 시작 평가액 + 당일 투자금
  - 현재 평가액: 모든 코인 현재 평가액
  - 손실률 = (현재 평가액 - 기준 자본) / 기준 자본 × 100
```

## 5. 기존 보유 코인 처리

### 핵심 아이디어

> "그룹 배치를 강제한다. 배치 전에는 시작 버튼을 누를 수 없다."

### 동작 흐름

#### [Step 1] 프로그램 시작
```
백그라운드에서 Upbit API 조회:
  - 보유 코인 확인
  - positions.json과 비교
```

#### [Step 2] 기존 보유 코인 감지 시
```
시작 버튼 비활성화 ❌

화면 상단 경고 배너 표시:
┌────────────────────────────────────────────┐
│ ⚠️ 기존 보유 코인 감지: BTC, ETH, XRP     │
│ 그룹에 배치한 후 거래를 시작할 수 있습니다.│
│ [배치하기] [도움말]                        │
└────────────────────────────────────────────┘
```

#### [Step 3] [배치하기] 클릭
```
┌──────────────────────────────────────────┐
│ 📥 기존 보유 코인 그룹 배치              │
├──────────────────────────────────────────┤
│ 발견된 코인:                             │
│                                          │
│ BTC: 0.05개 (평단: 100,000,000원)       │
│ ETH: 2개 (평단: 4,500,000원)            │
│ XRP: 10000개 (평단: 650원)              │
│                                          │
│ 그룹 선택:                               │
│ BTC → [대형코인 ▼] [새 그룹 생성]       │
│ ETH → [대형코인 ▼] [새 그룹 생성]       │
│ XRP → [알트코인 ▼] [새 그룹 생성]       │
│                                          │
│ 💡 팁:                                   │
│ • 건드리기 싫은 코인은 모든 기능을 OFF한 │
│   그룹에 배치하세요.                     │
│ • 나중에 그룹 간 이동도 가능합니다.      │
│                                          │
│              [완료] [취소]               │
└──────────────────────────────────────────┘
```

#### [Step 4] [완료] 클릭 후
```
1. Upbit API에서 평단가 가져오기
2. positions.json에 기록:
   {
     "KRW-BTC": {
       "group_id": "group_001",
       "imported": true,
       "average_price": 100000000,
       "total_quantity": 0.05,
       "executed_dca_levels": [],  // 레벨 0부터 시작
       "executed_tp_levels": [],
       "executed_sl_levels": []
     }
   }

3. 테이블에 표시
4. 시작 버튼 활성화 ✅
```

### 사용자 선택에 따른 활용

#### 완전히 무시하고 싶은 경우
```
"🔕 무시" 그룹 생성:
  - 매수: 수동
  - DCA: 사용 안 함
  - 익절: 사용 안 함
  - 손절: 사용 안 함

→ 아무것도 안 함 (단순 표시만)
```

#### 손절만 자동
```
"🛡️ 안전관리" 그룹 생성:
  - 매수: 수동
  - DCA: 사용 안 함
  - 익절: 사용 안 함
  - 손절: 자동

→ 큰 손실만 자동 차단
```

#### 완전 자동 관리
```
기존 그룹에 추가:
  - 매수: 수동 (이미 보유 중)
  - DCA: 자동
  - 익절: 자동
  - 손절: 자동

→ 이후 모든 관리 자동
```

## 6. 포지션 상태 관리

### 문제 상황

```
프로그램 실행 중:
  - BTC DCA 2단계까지 실행
  - executed_dca_levels: [1, 2]
  - 익절 1단계 실행
  - executed_tp_levels: [1]

프로그램 강제 종료 (재부팅 등)

프로그램 재시작:
  - executed_dca_levels가 메모리에만 있었음
  - 초기화됨 → DCA 1단계를 또 실행? ❌
```

### 해결: positions.json 파일

**역할:**
- 각 포지션의 진행 상황 영구 저장
- 재시작 시 완벽 복구
- 중복 실행 방지

**업데이트 타이밍:**
- DCA 실행 시 → 즉시 저장
- 익절 실행 시 → 즉시 저장
- 손절 실행 시 → 즉시 저장
- 전체 매도 시 → 포지션 삭제

**전체 매도 판단:**
```
Upbit API로 잔고 확인:
  - BTC 0개

positions.json에서 제거:
  - "KRW-BTC" 항목 삭제

다음 매수 시:
  - 완전히 새로운 포지션
  - executed_dca_levels: [] (초기화)
```

## 8. 보류된 사항

다음 항목들은 **자동매수 로직 논의 시** 결정:

### ⏳ 스캔 주기
```
현재 상황:
  - auto_trading_config.json에 scan_interval: 60초
  - 매수 신호를 얼마나 자주 체크할지

결정 필요:
  - 전역 설정? 그룹별 설정?
  - 하드코딩(60초 고정)?
  - WebSocket 실시간 감지?
```

### ⏳ 모니터링 방식
```
현재 상황:
  - 시가총액 상위 N개
  - 커스텀 리스트

새 시스템:
  - 그룹에 코인 직접 추가하므로 불필요?
  - 자동매수 로직과 연관
```

### ⏳ 전략 설정
```
현재:
  - strategy_type: "scalping" (고정)

향후:
  - 전략 선택 가능?
  - 그룹별 다른 전략?
  - 자동매수 로직 설계 시 결정
```

### ⏳ 매수 신호 생성 방식
```
질문:
  - 어떤 조건에서 매수 신호를 생성할까?
  - RSI? MACD? 볼린저밴드?
  - 그룹별로 다른 조건?
```

## 9. 구현 우선순위

### Phase 1: 핵심 데이터 구조 (2시간)
```
✅ trading_config.json 스키마 확정
✅ positions.json 스키마 확정
- GroupConfigManager 클래스 구현
  - CRUD 메서드
  - 유효성 검증
- PositionManager 클래스 구현
  - 읽기/쓰기
  - 복구 로직
```

### Phase 2: 기존 보유 코인 처리 (2시간)
```
- 시작 시 Upbit 보유 코인 체크
- 시작 버튼 활성화 조건
- 경고 배너 UI
- 배치 다이얼로그
  - 그룹 선택 드롭다운
  - Import 로직
```

### Phase 3: GUI 개편 (3시간)
```
- 테이블에 "그룹" 컬럼 추가
- "DCA/익절/손절" 컬럼 (자동/알림/사용안함 텍스트 표시)
- [그룹 관리] 버튼
- 그룹 설정 다이얼로그
  - 그룹명 입력
  - 코인 체크리스트
  - 매수 방식 라디오 버튼
  - 매수 금액 입력
  - DCA/익절/손절 3옵션 라디오 버튼
  - DCA/익절/손절 레벨 설정 버튼
```

### Phase 4: 전역 설정 다이얼로그 (1시간)
```
- [설정] → [전역 설정] 메뉴
- 리스크 관리 3가지
  - 최대 포지션 수
  - 최소 KRW 잔고
  - 일일 손실 한도
    - 손실률 입력
    - 동작 선택 (알림/전체매도)
```

### Phase 5: UnifiedTradingWorker (4시간)
```
- 기존 SemiAutoWorker + AutoTradingWorker 통합
- 그룹별 설정 읽기
- mode="alert" 처리 (알림만)
- mode="disabled" 처리 (건너뛰기)
- 리스크 관리 체크 통합
- 일일 손실 한도 로직
  - 09:00 리셋
  - 당일 거래 손익 계산
  - 도달 시 동작 (알림/청산)
```

### Phase 6: 테스트 및 디버깅 (2시간)
```
- 그룹 생성/수정/삭제 테스트
- 기존 보유 코인 Import 테스트
- 각 모드 조합 테스트
  - 자동/수동 매수
  - DCA/익절/손절 3옵션
- 포지션 복구 테스트
- 리스크 관리 테스트
```

**총 예상 시간: 14시간**

## 10. 핵심 결정 사항 요약

| 항목 | 기존 | 신규 | 이유 |
|------|------|------|------|
| 모드 선택 | 라디오 버튼 (2가지) | 그룹 시스템 | 유연성 |
| 매수 금액 | 전역 | 그룹별 | 코인마다 다르게 |
| 모니터링 | 시가총액/커스텀 | 그룹에 직접 추가 | 간단함 |
| DCA/익절/손절 | 2가지 (자동/없음) | 3가지 (자동/알림/없음) | 세밀한 제어 |
| 일일 거래 횟수 | 제한 | 삭제 | DCA 막힐 수 있음 |
| 일일 손실 한도 | 없음 | 추가 (2가지 동작) | 리스크 관리 |
| 일일 리셋 | 00:00 | 09:00 | 업비트 등락률 기준 |
| 손실 계산 | - | 당일 거래만 | 직관적 |
| 기존 보유 코인 | 모호함 | 그룹 배치 강제 | 명확함 |
| 포지션 상태 | 메모리 | positions.json | 재시작 복구 |
