## 테스트 시나리오

### 🧪 **테스트 1: 프로그램 시작 시 기존 보유 종목 표시**

**목적**: 문제 1 해결 확인 - 시작 버튼 누르기 전에 보유 종목이 표시되는지

**준비**:
- Upbit 앱에서 미리 코인 1-2개 보유 (예: BTC, ETH)
- 프로그램 종료 상태

**테스트 절차**:
```
1. 프로그램 실행 (python main.py)
2. GUI 로그 확인:
   [예상]
   - "🔄 초기화 시작..."
   - "🔄 초기화 중... (1/3) 예수금 조회"
   - "✅ 예수금 조회 완료: XXX,XXX원"
   - "🔄 초기화 중... (2/3) 보유 종목 조회"
   - "✅ 보유 종목 2개 발견: BTC, ETH"
   - "   → 활성 포지션 테이블에 표시 완료"  ← 새로운 로그!
   - "🔄 초기화 중... (3/3) 실시간 감지 준비"
   - "✅ 실시간 감지 준비 완료!"

3. 활성 포지션 테이블 확인:
   [예상]
   - BTC, ETH가 이미 테이블에 표시되어 있어야 함
   - 진입가, 현재가(=진입가), 손익(0원, 0%) 표시

4. 시작 버튼 상태 확인:
   [예상]
   - "▶ 전체 DCA 시작" 버튼 활성화됨
   - MyAsset 상태: "✅ 실시간 감지 준비 완료!"
```

**성공 기준**:
- ✅ 시작 버튼 누르기 전에 보유 종목이 테이블에 표시됨
- ✅ 로그에 "활성 포지션 테이블에 표시 완료" 메시지 출력
- ✅ 테이블의 종목 개수 = 실제 보유 종목 개수

**실패 시**:
- 테이블이 비어있거나 일부만 표시되면 실패
- 스크린샷 + 로그 제공

### 🧪 **테스트 2: 프로그램 시작 직후 즉시 매수 (KRW 변동 트리거 테스트)**

**목적**: 문제 2 개선 확인 - KRW 변동 시에도 스캔 트리거되어 빠른 감지

**준비**:
- 프로그램 종료 상태
- Upbit 앱 열어두기 (빠른 매수용)
- 초시계 준비 (타이밍 측정)

**테스트 절차**:
```
1. 프로그램 실행 (python main.py)
2. "✅ 실시간 감지 준비 완료!" 메시지 나오자마자:
   → 초시계 시작

3. 시작 버튼 클릭
4. 즉시 Upbit 앱에서 소액 코인 매수 (예: XRP 5,000원)
   → 매수 시각 기록 (예: 14:25:30)

5. CLI 로그 실시간 모니터링:
   [예상 로그 순서]

   14:25:30 - [사용자 매수 실행]

   14:25:XX - 📨 MyAsset 메시지 수신: {'type': 'myAsset', 'assets': [{'currency': 'KRW', ...}]}
   14:25:XX - 💰 자산 변동 감지: KRW - 잔액: XXX,XXX원
   14:25:XX - 🔍 자산 변동 감지 (KRW) → 즉시 포지션 스캔  ← 핵심!
   14:25:XX - 🔔 새로운 수동 매수 감지: 1개 종목 처리 중...
   14:25:XX - 🔍 XRP 신규 포지션 등록

   또는

   14:25:YY - 📨 MyAsset 메시지 수신: {'type': 'myAsset', 'assets': [{'currency': 'KRW', ...}, {'currency': 'XRP', ...}]}
   14:25:YY - 💰 자산 변동 감지: KRW - 잔액: XXX,XXX원
   14:25:YY - 💰 자산 변동 감지: XRP - 잔액: X.XXXXXXXX
   14:25:YY - 🔍 자산 변동 감지 (KRW, XRP) → 즉시 포지션 스캔  ← 핵심!
   14:25:YY - 🔔 새로운 수동 매수 감지: 1개 종목 처리 중...

6. 감지 시간 측정:
   → 초시계 종료
   → 매수 시각 ~ "새로운 수동 매수 감지" 시각 계산
```

**성공 기준**:
- ✅ 로그에 "📨 MyAsset 메시지 수신" 출력됨
- ✅ KRW 변동만 있어도 "🔍 자산 변동 감지 → 즉시 포지션 스캔" 트리거됨
- ✅ 감지 시간 ≤ 2분 (이상적으로는 15-60초)
- ✅ 활성 포지션 테이블에 XRP 표시됨

**주의**:
- 이 테스트는 프로그램 **첫 실행 직후**이므로 Upbit 정책상 1-3분 지연 가능
- 감지 시간이 2-3분이어도 정상 (Upbit 서버 정책)
- 중요한 것은 **KRW 변동 메시지에서도 스캔이 트리거**되는지 확인

**실패 시**:
- "자산 변동 감지 → 즉시 포지션 스캔" 로그가 없으면 실패
- 3분 이상 지연되면 로그 전체 제공

### 🧪 **테스트 3: 두 번째 매수 (실시간 감지 최적화 확인)**

**목적**: Upbit "수분간" 정책이 지난 후 정상 감지 확인

**준비**:
- 테스트 2 완료 상태
- 프로그램 계속 실행 중 (재시작 X)
- 첫 매수 후 **5분 이상 대기**

**테스트 절차**:
```
1. 첫 매수 후 5-10분 대기
   → 이 시간 동안 Upbit의 "수분간" 정책이 지나감

2. 다시 소액 코인 매수 (예: DOGE 5,000원)
   → 매수 시각 정확히 기록
   → 초시계 시작

3. CLI 로그 모니터링:
   [예상 로그 - 훨씬 빠름!]

   14:35:20 - [사용자 매수 실행]
   14:35:35 - 📨 MyAsset 메시지 수신: {...}  ← 15초 후!
   14:35:35 - 💰 자산 변동 감지: KRW
   14:35:35 - 💰 자산 변동 감지: DOGE
   14:35:35 - 🔍 자산 변동 감지 (KRW, DOGE) → 즉시 포지션 스캔
   14:35:35 - 🔔 새로운 수동 매수 감지: 1개 종목 처리 중...

4. 감지 시간 측정:
   → 초시계 종료
   → 기대값: 15-30초 (최대 60초)
```

**성공 기준**:
- ✅ 감지 시간 ≤ 60초 (이상적으로는 15-30초)
- ✅ 활성 포지션 테이블에 DOGE 즉시 추가됨
- ✅ 로그에 MyAsset 메시지 전체 내용 출력됨

**비교**:
| 시나리오 | 첫 매수 (테스트 2) | 두 번째 매수 (테스트 3) |
|---------|------------------|---------------------|
| 감지 시간 | 1-3분 (Upbit 정책) | 15-60초 (실시간) |
| 원인 | 최초 구독 "수분간" 대기 | 정상 실시간 감지 |

**실패 시**:
- 60초 초과 시 로그 + 네트워크 상태 제공

## 문제 해결 가이드

### Q1: 테스트 1에서 보유 종목이 표시되지 않아요
→ 로그에 "활성 포지션 테이블에 표시 완료" 메시지가 있는지 확인
→ 로그 전체 + 스크린샷 제공

### Q2: 테스트 2에서 5분 이상 지연돼요
→ Upbit 정책상 정상일 수 있음
→ 하지만 "📨 MyAsset 메시지 수신" 로그가 있는지 확인
→ 메시지는 왔는데 감지 안 되면 로그 제공

### Q3: 테스트 3에서도 2-3분 지연돼요
